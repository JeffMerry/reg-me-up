F07 implementation/test evidence is recorded separately in [F07 evidence](f-07-evidence.md); implementation peer review remains a separate gate. Owner JeffMerry. ## Scope and workflow

Organizer opens Check-in on an event they own, reads its ACTIVE registration roster and attendance states, confirms a participant's check-in, and receives a persisted result. Participant/Instructor/anonymous cannot read the private roster or mutate attendance. A teaching assignment does not grant Organizer privileges. No QR, bulk upload, notifications, self check-in, manual clock input or attendance correction/undo is added.

Only an ACTIVE registration on that exact event is eligible. New attendance requires startsAt≤decisionTime<endsAt, including start and excluding end, with one trusted server time sampled after the event lock. A CANCELLED history row remains ineligible even if the same participant registered again: the new registration ID must be used. Wrong-event/missing registration is404 without another event's metadata. Existing valid attendance returns its original persisted record/time without creating another row. Proposed response precedence for review: after owner/exact registration/ACTIVE checks, return existing attendance200 before the creation-window check; this treats a repeat outside the window as reading the already recorded outcome, not new check-in. No new attendance is allowed outside the window.

## Feature SDS / data / transaction

Add Attendance: id UUID PK; registration_id UUID UNIQUE FK registrations RESTRICT; checked_in_at timestamptz NOT NULL; checked_in_by UUID FK users RESTRICT. Event/participant derive from Registration rather than duplicate mutable fields. The service verifies the actual session actor owns the event; DB FK is not a substitute for role/ownership validation. Initial migration files/checksums and historical registration rows are preserved; no seed/reset/attendance backfill from browser state.

Use existing withEventWrite event scope, READ COMMITTED and bounded timeouts. Order: authenticate/Organizer/CSRF/JSON → UUID/body/query validation → event row lock → owner lookup → exact registration→ACTIVE → existing attendance → sample trusted clock/window → insert attendance → commit. Sample the creation clock once under lock; read/no-op never alters time. A UNIQUE registration constraint is a second line of defense. No schedule advisory mutex is needed: check-in does not edit event time/Instructor, and must never acquire the mutex after holding an event lock. F05 cancellation/F06 edits share the event lock, so eligibility/time changes are read after waiting. Repeated/concurrent same-ID requests return one original attendance; rollback leaves no partial attendance. Known contention503 TEMPORARILY_UNAVAILABLE; uncertain write503 OUTCOME_UNKNOWN; UI requires authorized GET reconciliation, not automatic POST retry.

GET roster uses an authorized consistent read: published/private event metadata needed by owner, window state from server, active registrations ordered registeredAt/id ASC; pagination page/pageSize20/max100; summary derives counts from persisted state. Response rows contain registrationId, participant displayName, registeredAt and attendance{id,checkedInAt} or null; no emails/hash/session/other-event data. Participant identity is implicit in registration, never accepted from the client. Read DTO does not expose arbitrary assignment history or private credentials.

## API and errors

| Method/path | Input | Result |
|---|---|---|
| GET /api/organizer/events/:eventId/check-ins | Organizer owner; page/pageSize only | 200 owner event/window metadata, ACTIVE roster and attendance; empty roster is successful empty data |
| POST /api/organizer/events/:eventId/registrations/:registrationId/check-in | Organizer owner, CSRF/Origin; body{} and no query | 201 new attendance;200 original attendance on valid repeat |

401 anonymous/expired;403 wrong role/CSRF/Origin;404 non-owner/event/registration missing or wrong-event;422 invalid UUID/body/query/unknown fields;409 REGISTRATION_INELIGIBLE for CANCELLED own-event row;409 CHECK_IN_NOT_OPEN before start;409 CHECK_IN_CLOSED at/after end. Error bodies are safe code/message, field errors only for input; never disclose another owner's registrant. Any denial/failed transaction preserves registrations/event/version/attendance. Check-in does not increment management events.version or change capacity/ACTIVE count.

The shared strict JSON parser returns400 for malformed JSON or top-level scalar/null before route validation; arrays/invalid object fields reach the validator and return422. No parser/session policy is changed by F07.

## UI

Separate owner Check-in view linked from My Events; Thai time label/UTC serialization, server status determines ability. Each row distinguishes Not checked in/Checked in timestamp, confirmation and pending. Disable repeated submit while pending. Show loading, empty, read error with retry, invalid/ineligible/window closed, forbidden/missing, expiry clearing private cache, and uncertain outcome with explicit Check status. Reload/reconcile reads saved attendance before enabling another mutation. Confirmation supports keyboard/focus/Escape when not pending, focus restore and320/390/1440 layout. Never show successful attendance from local state before a successful server result.
