## Workflow and Feature SDS

Organizer opens own event management, reads paginated Instructor directory (id/displayName only), selects one and confirms assignment with expectedVersion. Replacement closes old assignment and creates current history in one transaction; same current Instructor is a no-op. Removal ends current history; repeated empty removal no-op with valid write preconditions. Mutations allowed only before existing event start. Shared event version prevents stale edits; schedule mutex serializes cross-event overlap checks with F-06 event time edits. Half-open intervals allow exact adjacency. Assignee absent/wrong-role is the same safe422 instructorId validation; competing event details are never returned.

Instructor logs in using existing lifecycle and sees My Teaching current list/detail. Unassigned resource404; replaced/removed Instructor loses protected teaching access immediately on next read. Historical assignments stay in DB, not exposed by this scope. Public event list/detail remains public for every role; permission to read public metadata never grants access to registrants or private assignments.

Data/routes/DTO/indexes/lock design are in [system design](system-design.md). UI adds owner assignment select/replace/remove confirmation, pending/empty/error/conflict handling and Instructor navigation/list/detail with pagination. Update frontend/backend identity unions and safe returnTo allowlist; preserve server authorization even when links hidden. No self-sign-up, multi-role account admin, emails/passwords in directory, Instructor cancellation/publish/edit rights, or notifications.

Explicit synthetic local/test Instructor fixtures and a separately reviewed demo provision procedure are required. Existing accounts/passwords remain untouched. Provisioning uses role-correct records with salted hashes, runtime secret inputs and no automatic seed on startup/deploy. Stack/config/cookie/expiry unchanged.
