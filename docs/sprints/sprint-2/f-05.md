## Workflow, UI/API/data

Own ACTIVE registration detail shows Cancel registration before startsAt with a confirmation modal and no optimistic seat change. Confirm POSTs own ID/body{} with CSRF. Success refreshes own detail/list and availability from server. Repeated cancellation of the same CANCELLED ID returns200 without timestamp changes or additional seat return. A new registration after cancellation creates another ID and leaves history intact; cancelling the old ID cannot affect it. Failed/denied operations leave all rows unchanged.

Endpoint, state CHECK, timestamp, event-lock order and safe errors follow system-design.md §§1–3. UI-04/04-D gains ACTIVE/CANCELLED labels, cancellation confirmation/pending/closed/error/unknown-outcome states. Use accessible modal focus/Escape/restore and disabled repeat submit while pending. For unknown response, reload own detail before retry; no fabricated success. Owner summary remains ACTIVE-only. Stack/auth/public discovery APIs need no architectural change, but nested registration DTOs/UI need explicit regression.
