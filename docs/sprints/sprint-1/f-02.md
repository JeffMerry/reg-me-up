## 1. Workflow and scope

Organizer logs in → My Events → Create Event → validate → publish once → wait for committed server response → success and public detail. Server derives organizer ID from authenticated user. Anonymous/Participant/Organizer browse published list/detail without private registration data; full events remain visible. My Events comes from an owner-filtered backend response, not client filtering.

No event edit/delete/draft/unpublish/deadline/Instructor/upload/search/filter controls. Description optional; cover is prepared/default asset, not upload input. No future-start or start/end registration cutoff in Sprint 1. Unknown publication outcome preserves form and offers My Events check before resubmitting; no automatic retry or exactly-once-publication promise.

## 2. API and field contract

| Method/path | Access / request | Success |
|---|---|---|
| GET `/api/events?page=1&pageSize=20` | Public | 200 `{data:EventPublic[],meta:{page,pageSize,total}}`, published only, startsAt/id ASC |
| GET `/api/events/:eventId` | Public UUID path | 200 `{data:EventPublic}`; unknown/unpublished 404; malformed UUID 422 |
| POST `/api/events` | Organizer + session/Origin/CSRF; fields below | 201 `{data:EventOwned}` only after insert committed; published record/owner set server-side |
| GET `/api/me/events?page=1&pageSize=20` | Organizer | 200 own EventOwned rows/meta; createdAt/id DESC |

DTOs/pagination/error envelope are defined once in [SDS §5](../../system-sds.md). Public and own responses must not return registrant objects/email/hash/session fields. Before F-03 behavior is implemented, the registration table/constraints can be created to support counts; no registration mutation belongs in this feature. A constant hardcoded count is not the final F-02 read contract.

| Field | Input / normalization | Rejection |
|---|---|---|
| title | Required string; trim; 1–200 code points | Missing/null/blank/over limit → field error |
| startsAt | Required actual ISO8601 datetime with explicit Z/offset | Invalid/naive datetime → field error |
| endsAt | Same encoding; strictly after startsAt | Equal/reversed/invalid → field error |
| location | Required string; trim; 1–300 code points | Missing/null/blank/over limit → field error |
| capacity | JSON number integer 1–2147483647 | Missing/null/string/0/negative/fraction/overflow → field error |
| description | Optional string/null, max10000 code points; omitted/blank → null | Wrong type/over limit → field error; never required |

Only these six fields accepted; client owner/status/ID/image fields rejected 422. Validation errors use 422 VALIDATION_ERROR with safe fieldErrors and no event inserted. Protected access: anonymous401, Participant403; malformed transport/CSRF per SDS. Unexpected DB errors rollback/no success; lost connection after commit has unknown outcome and requires state reconciliation.

## 3. Data and UI

Data migration: events FK/checks/indexes per SDS; created ID, organizer owner, PUBLISHED status and timestamps assigned server-side. No Instructor/Attendance migration. Publish is one atomic insert with required constraints. Remaining/count fields computed from ACTIVE registrations with consistent read snapshot; never trust UI seat count. Owner list is always organizer_id=session user ID, with no selector/override.

UI-02 cards list title/date range/location/remaining/status and details link with loading/empty/error; UI-03 hides description section when empty and uses public metadata only. UI-05 shows own event counts/capacity; UI-06 has exactly required form fields plus optional description, field errors/first-invalid focus/pending state. UI-S02 safe not found. See [UI baseline](../../ui-spec.md) for layout/tokens/mobile/keyboard states.

Start/end inputs/display use Asia/Bangkok UTC+7 and convert to offset-bearing instants; server returns UTC. End after start is validated on both layers. No inference that event full means closed by deadline. Cancel in Create Event means leave unsaved form without creating row, not cancellation of registration; unsaved changes require discard confirmation per baseline.
