## 1. Behavior and boundaries

Login/logout/current identity must work through UI→API→PostgreSQL-backed session store. Session identifies a server user; role cannot be selected in the browser. Resource ownership is enforced in F-02–04 services as well as shared role guards. No signup/recovery/Admin/Instructor UI in Sprint 1.

Use all shared authentication/CSRF/cookie/hash rules in [SDS §§2/4/5](../../system-sds.md). Authenticated lifetime is absolute 8 hours; expiry is `now >= authenticatedAt+8h`. Regenerate SID and rotate CSRF on login; logout destroys stored session and clears cookie. Read user role from database for each authenticated request. Do not store password/hash in session or return it.

Main flow: UI bootstrap CSRF → login credentials → session persisted/identity returned → safe returnTo or role default. Identity endpoint determines logged-in state. Anonymous protected navigation goes to login; authenticated wrong role shows Access Denied. Login must never automatically register for an event.

## 2. API contract

| Method/path | Preconditions / input | Success | Failures |
|---|---|---|---|
| GET `/api/auth/csrf` | Public; existing or new anonymous session | 200 `{data:{csrfToken}}` and session cookie if needed | Safe 500/store unavailable error; never return authenticated identity as token |
| POST `/api/auth/login` | Configured Origin + session CSRF header; JSON `{email,password}` only | 200 `{data:{user:Identity,csrfToken}}` with new SID and token; save session before response | 403 CSRF_INVALID; 422 fields invalid; 401 INVALID_CREDENTIALS; safe server error |
| GET `/api/auth/me` | Authenticated unexpired session | 200 `{data:Identity}` | 401 UNAUTHENTICATED |
| POST `/api/auth/logout` | Authenticated session + Origin/CSRF; JSON `{}` | 204, no body; destroy SID and clear matching cookie | 401; 403 CSRF_INVALID; safe server error, never false success |

Identity = `{id,displayName,role}` per SDS; every response no-store. Email trim/lowercase/format/max254; password unchanged/nonempty/max1024 UTF-8 bytes. Unknown fields 422. Generic invalid message: `Incorrect email or password.` for unknown email and wrong password, without account-existence detail. Valid re-authentication uses same regeneration flow and invalidates previous SID; no privilege change based on payload.

Anonymous pre-auth session is not authenticated access. On failed login `/me` stays 401 unless caller already had a valid authenticated session; login failure must not authenticate the submitted account. Tests use fresh anonymous session for invalid-login assertion.

## 3. UI and data changes

UI-01 and shared navbar/guards follow [UI baseline §§3/5](../../ui-spec.md): real email/password labels, show/hide button not submitting, password manager/paste, pending disabled submit, field/server/network messages, browse-public action. Preserve email after failure; never trim/log password. Success uses server identity/new CSRF then reloads destination state. Session-loading placeholders prevent private flash.

Allowlisted returnTo paths and role defaults are defined in SDS; reject external/protocol-relative/wrong-role return paths. Organizer returning to public event has no enabled registration. Logout shows progress, clears private cached state only when success/known expired identity handled; failed request does not claim successful logout. Expiry clears private data and allows public detail to remain visible. Back navigation rechecks access.

Data: SYS-01 owns the initial users and adapter-required session schema and Prisma Migrate history; F-01 consumes that baseline and implements the authentication behavior. Any later necessary schema change requires a new reviewed migration. User role and hash constraints per SDS; Argon2id m=19456 KiB/t=2/p=1 with library salt. Version the chosen store schema in Prisma migrations; no unversioned auto-create in deployed startup. No event/registration table change in this feature.
