## 1. Workflow and scope

Organizer opens My Events → event's View registrations → backend verifies role and owner → authorized event metadata, counts and registrant rows displayed. Another Organizer still may read that event's **public detail** but cannot read this private response. Never fetch/render private metadata before ownership is established.

No check-in/cancel/export/edit/report/chart actions. This feature is read-only; no domain mutation/table migration expected beyond existing schemas/indexes. If query tuning needs an index, record separate versioned migration and rationale; do not silently change schema.

## 2. API and read model

GET `/api/organizer/events/:eventId/registrations?page=1&pageSize=20`

Require authenticated Organizer; UUID validation; owner-filtered resource lookup before rows/counts/DTO construction. Missing event or non-owner →404 NOT_FOUND with identical safe shape, no private event name/totals. Anonymous401, Participant403, malformed UUID/query422. GET does not require CSRF and never writes.

Success200 OwnerRegistrations per [SDS §5](../../system-sds.md):

- `data.event`: EventPublic metadata from authorized event.
- `data.summary`: capacity, activeRegistrations, remainingSeats from server.
- `data.registrations`: ACTIVE RegistrantRow entries with registration ID, displayName, registeredAt and status only.
- `meta`: page/pageSize/total; rows registeredAt ASC/id ASC, default20/max100; total counts all authorized active rows, not current page length.

No registrant email/phone/hash/session/user-ID fields. Rows/total/summary share a consistent read snapshot. Wrong owner must never receive event-private metadata/registrants/totals even when they know the UUID; response no-store and no stale private client cache. Empty owner event returns200 with [] and correct zero/count/capacity summary, not404.

## 3. UI and data design

UI-05 navigation → UI-07 per [UI baseline](../../ui-spec.md): breadcrumb/title/date/location, registration/capacity/remaining summary, desktop table/mobile cards. Loading skeleton; empty means no registrations; server/network error has retry and does not masquerade as empty. Forbidden/not-found clears previously shown event and cached private content. Display row numbering according to page offset; server totals remain authoritative.

Data reads join registrations to users only after owner-authorized event selection. Map exactly safe fields; do not serialize `SELECT *` to client. Reuse initial Event/Registration constraints and indexes from SYS-01; depend on F-02/03 for event ownership and registration behavior. API/application is changed for authorized query/DTO; UI changes are UI-07 and links; no new domain write path.
